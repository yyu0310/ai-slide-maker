# 投影片製作指南

這份指南收錄要靠判斷的部分：怎麼拆頁、圖片怎麼放、哪些話該留在講稿。能用程式判斷的規則已經寫進模板和檢查工具，不需要背。[做簡報的完整流程](workflow.zh-TW.md)另有一份。

## 一個檔案就是整份簡報

- 開頭的 CSS 決定整份簡報的樣式，內文用 `---` 分頁。
- `<!-- -->` 裡的文字是講稿，觀眾看不到，匯出 PowerPoint 時會變成演講者備註。
- 用 `slides.py map` 可以列出每一頁對應的行號。

| 效果 | 寫法 |
| --- | --- |
| 分頁 | `---` |
| 封面、結尾 | `<!-- _class: lead -->` |
| 章節轉場 | `<!-- _class: part -->` |
| 內容靠上排（預設會垂直置中） | `<!-- _class: top -->` |
| 內容較多的頁面 | `<!-- _class: dense -->` |
| 隱藏頁碼 | `<!-- _paginate: false -->` |
| 這頁不要頁首、頁尾 | `<!-- _header: '' -->`、`<!-- _footer: '' -->` |
| 一頁用兩個 class | `<!-- _class: top dense -->`，寫在同一行。寫成兩行時後者會蓋掉前者 |
| 頁面上方的小標 | `<div class="kicker">文字</div>`，和標題之間要空一行 |
| 小字 | `<span class="small">文字</span>` |
| 標籤 | `<span class="tag">文字</span>` |
| 圖片限高 | `![h:300](./assets/圖片.png)` |
| 左文右圖 | `![bg right:40% contain](./assets/圖片.png)` |
| 兩欄 | 見下方 |

兩欄要照這樣留空行：

```html
<div class="cols">
<div>

**左欄標題**

- 重點

</div>
<div>

**右欄標題**

- 重點

</div>
</div>
```

## 什麼時候該拆頁

一頁只講一件事。`check` 會告訴你內容有沒有被切掉，也會建議怎麼修，但塞得下不代表好讀。

- 超過 5 到 6 個重點，或有 2 段以上的長文字：拆頁。
- 表格超過 5 列：拆頁，或這頁改用 `dense`。
- 有圖的頁面，文字控制在 3 到 4 行。
- 表格圖太寬時，只節錄表頭和重點列，並在圖說註明其餘省略。
- 標題寫成一句主張，例如「成長來自回頭客」，不要只寫「營收分析」。

## 圖片怎麼放

| 情況 | 寫法 | 說明 |
| --- | --- | --- |
| 圖文並列 | `![bg right:40% contain]` | 截圖和圖表加 `contain`，完整顯示；人像和照片不加，填滿版面 |
| 圖片是主角 | 獨立一頁，`![h:520]` | 長截圖、新聞圖適合，會自動避開頁首頁尾 |
| 全版背景 | `![bg]` | 頁首頁尾文字會疊在圖上變得難讀，這頁要清掉 `_header` 和 `_footer` |
| 圖放在文字下方 | 標題和文字在上，`![h:300]` 在下 | 不要夾在兩段文字中間 |

圖片放進 `assets/`，命名為 `p{頁碼}_{主題}.png`，例如 `p17_revenue.png`，在資料夾裡一眼就能對到頁面。路徑有空格時要包起來：`![](<my assets/chart.png>)`。

## 表格還是時間軸

- 比較和清單用表格。
- 依序發生的事用時間軸，每項一段，中間放一行 `↓`。
- 粗體只包數字：寫 `↓ **80%**`，箭頭才不會跟著變色。

## 投影片和講稿的界線

投影片是給觀眾看的成品。講者要提醒自己的話都放講稿。

| 內容 | 放哪裡 |
| --- | --- |
| 哪個數字要再確認、被追問時怎麼答 | 講稿 |
| 資料年份、樣本範圍、來源 | 投影片的資料來源或圖說，例如「資料來源：2025 年問卷，212 份」 |
| 結論本身有不確定性 | 用「可能」「傾向」這類措辭寫在投影片 |

## HTML 的三個陷阱

- `style="..."` 會被濾掉。樣式寫成 CSS class，放在檔案開頭。
- `<div>` 裡要用 Markdown，開始標籤後和結束標籤前都要留空行。
- HTML 區塊裡，空行後接 4 格縮排會變成程式碼區塊。

## 匯出節奏

- 每做完一個 Part 就匯出一次，看總覽圖，不要等全部做完才一次修排版。
- 初稿完成或大改之後跑一次 `/ai-slide-maker:review`。小修字不用跑。

## 長短兩個版本

完整版穩定後，複製一份再刪減成演講版。不要直接改完整版，這樣它永遠可以重新產出短版。

## 做不到的畫面

- 地圖、架構圖這類版面，用程式畫成圖片再放進 `assets/`。
- 全出血照片加文字需要高解析原圖。
- 複雜的多欄浮動排版不適合，改成圖片或拆頁。

## 能力範圍

| 項目 | 現況 |
| --- | --- |
| 逐項出現 | 這個工具的輸出做不到，PDF 和 PowerPoint 都會全部顯示 |
| 影片 | 無法嵌入，要在 PowerPoint 手動插入 |
| PowerPoint | 每頁是一張圖，版面完全一致，文字不能直接改；講稿會保留 |
| 可編輯 PowerPoint | 刻意不採用。Marp 實驗性的 `--pptx-editable` 實測會弄丟講稿和圖片，部分中文字也會變成外形相近的部首字元 |
| 從舊 PDF 重建 | 文字為主的簡報容易重建；視覺型簡報需要原始素材 |

## 自動檢查對照

`qa` 不用開瀏覽器，幾乎立刻跑完。`check` 會實際渲染每一頁。FAIL 要處理，WARN 是提醒。

| 代號 | 抓什麼 | 層級 |
| --- | --- | --- |
| Q1 | 投影片上有 TODO、【待補】這類草稿標記 | FAIL |
| Q2 | 圖片檔案不存在，或路徑有空格卻沒用 `<>` 包起來 | FAIL |
| Q2R | 用了網路圖片，沒網路時可能顯示不出來 | WARN |
| Q3 | 給講者的話出現在投影片，例如「待確認」 | FAIL |
| Q3W | 可能是給自己的話，例如「我猜」「推測」 | WARN |
| Q4 | 模板的 `{{...}}` 沒換掉 | FAIL |
| Q5 | `style=` 會被濾掉 | WARN |
| Q6 | HTML 標籤後沒有空行，後面的 Markdown 不會生效 | WARN |
| Q7 | 空行後的縮排會變程式碼區塊 | WARN |
| Q8 | 粗體包到箭頭 | WARN |
| Q9 | 全版背景圖壓到頁首頁尾 | WARN |
| Q10 | 圖檔還是截圖預設名稱 | WARN |
| Q11 | 同一頁有兩個 `_class` 註解 | WARN |
| Q12 | 引用簡報資料夾以外的檔案，匯出時會被帶進成品 | FAIL |
| Q13 | 註解沒有結尾，後面的投影片都會消失 | FAIL |
| C1 | 內容超出頁面被切掉 | FAIL |
| C2 | 內容壓到頁首或頁尾 | WARN |
| C3 | 字小於 16px，投影時看不清楚 | WARN |
