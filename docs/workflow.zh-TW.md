# 做一份簡報的流程

這是作者從接到題目到上台實際走的四步。前三步由 AI 陪你做，第四步是上台當天的檢查清單。

| 步驟 | 產出 | 指令 |
| --- | --- | --- |
| 1. 題目與受眾 | 一句話定位 | `/ai-slide-maker:new` |
| 2. 內容大綱 | `outline.md` | `/ai-slide-maker:new` |
| 3. 製作投影片 | `slides.md`、PDF | `:new`、直接用講的修改、`:review`、`:export` |
| 4. 上台當天 | 設備和備份 | 自己確認 |

## 1. 題目與受眾

動手前先回答四件事：

- 目的：說服、教學，還是分享
- 受眾：學生、業界，還是混合，他們已經知道什麼
- 時間：幾分鐘
- 主辦方有沒有格式或工具限制

然後寫出一句話：**讓誰，在多少時間內，學到什麼。** 這句話定不下來，後面的簡報就會發散。

## 2. 內容大綱

先選一種結構：

| 結構 | 順序 | 適合 |
| --- | --- | --- |
| 故事弧線 | 背景、轉折、發展、高潮、解決 | 分享經驗、創業故事 |
| 三段式 | 問題、分析、解法 | 提案、報告 |
| 案例驅動 | 每個段落由一個具體案例帶出 | 教學、科普 |

每個段落確認三件事：

- 一句話核心訊息
- 用哪個案例、數據或互動
- 預估時間

大綱定案後才開始做投影片。在這一步改方向最便宜。

## 3. 製作投影片

1. 依大綱一個段落一個段落做，每做完一段就匯出看總覽圖。
2. 講者要說的話寫進講稿，投影片只留觀眾需要看的內容。
3. 圖片放進 `assets/`，命名為 `p{頁碼}_{主題}.png`。
4. 初稿完成後跑 `/ai-slide-maker:review`，讓三種讀者挑問題，你逐條決定怎麼處理。
5. 最後跑 `/ai-slide-maker:export`，通過檢查才匯出。

時間比較短的場次，等完整版穩定後複製一份刪減，不要直接改完整版。

資料夾長這樣：

| 檔案 | 用途 |
| --- | --- |
| `slides.md` | 簡報本體，含講稿 |
| `slides.pdf` | 匯出的成品 |
| `outline.md` | 大綱 |
| `assets/` | 圖片 |

## 4. 上台當天

不依賴主辦方，每個環節都自己確認。

- 自備 HDMI 和 USB-C 轉 HDMI 轉接頭，出門前試過
- 備份兩份：USB 隨身碟和雲端連結
- 提早到場接線，確認畫面是 16:9
- 關閉通知和螢幕保護程式，開勿擾模式

更細的排版判斷見[投影片製作指南](guide.zh-TW.md)。
